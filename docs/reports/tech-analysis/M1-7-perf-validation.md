## 1. 口径与方法

- 脚本：`scripts/perf-validate.mjs`（根目录 `pnpm perf`）；原始数据：
  - `docs/reports/tech-analysis/M1-7-raw.json`（三仓库 × 3 页）
  - `docs/reports/tech-analysis/M1-7-raw-linux-deep.json`（torvalds/linux × 11 页）
- 指标定义：**TTFB** = 响应头到达耗时；**总耗时** = 读完响应体耗时；**接口请求数** = 时间线翻页对应的服务端请求数（每页 1 次上游 GraphQL）。
- 首屏口径：本机无浏览器，用「仓库页 HTML 的 TTFB + 传输耗时」近似「首屏可交互」；Lighthouse 分数需部署公网后实测。
- 样本：小 = `encode-utf8/utf8-git`（17 commits）、中 = `encode-utf8/stock-analysis`、大 = `torvalds/linux`。

## 3. 结论

- **缓存收益显著**：仓库列表回源 1795.8 ms → 命中缓存 37.0 ms（≈48×）；时间线命中页 23–42 ms，回源页 2.1–3.1 s。
- **翻页请求数符合设计**：时间线每页 1 次上游请求，翻 N 页 = N 次；已加载页不重复请求。
- **翻页无重复**：`torvalds/linux` 连续 11 页共 550 条提交，去重后仍为 550（0 重复）；订单（时间倒序）与游标推进正常。
- **热缓存首屏达标**：三仓库 HTML TTFB 58–64 ms，远低于 2 s 目标。
- **冷缓存首屏未达标（本地口径）**：1.83–2.27 s，主要来自 经本地代理访问 GitHub 的往返（单页 GraphQL 约 2.1–3.1 s），并非应用层开销；需在真实部署环境复测。
- **冷启动**：本机生产模式实例 Ready 1.5–2.3 s，作为 roadmap「冷启动 < 3 s」的近似参考；Vercel 上需实测。

## 4. 发现的问题与处理

| 问题                            | 影响                                                                                                                                                 | 处理                                                                                                                                                                          |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 翻页越界会重复第 1 页数据       | 上一页 `endCursor` 为 `null`（已无更多数据）时，后续页仍以 `null` 游标请求，GitHub 忽略 `after` 并返回第 1 页；实测 `utf8-git` 第 3 页重复返回 17 条 | 已修复：`timeline-data.ts` 遇到 `endCursor === null` 时直接返回空页（复用上一页仓库信息）；上一页数据不可用时回退 409 `cursor_expired`。补充 2 个单测，端到端复测跨页重复 = 0 |
| 本地网络需代理访问 `github.com` | 令牌续期端点不可直连（`api.github.com` 可直连），无代理时续期超时 → 504                                                                              | 验证时通过启动脚本注入 `NODE_USE_ENV_PROXY` + `HTTPS_PROXY`；生产环境不需要（已记入 `docs/deployment.md`）                                                                    |

## 5. 未验证项与后续建议

- **Lighthouse ≥ 80**：需部署公网后用浏览器实测（本机仅有服务端耗时近似）。
- **1000+ 提交滚动流畅度**：虚拟滚动是客户端行为，本机无浏览器无法量测；服务端侧已证明 550 条连续翻页无重复、无乱序，建议公网部署后补一次大仓库滚动实测（可继续加大 `PERF_PAGES`）。
- **冷缓存首屏 < 2 s**：需在真实部署（数据中心 → GitHub）复测；若仍偏高，可考虑首屏预取第 1 页 + 骨架屏优先渲染。
- **复现方式**：`PERF_COOKIE="authjs.session-token=<令牌>" PERF_BASE_URL=<地址> pnpm perf`（可选 `PERF_REPOS` / `PERF_PAGES` / `PERF_JSON` 覆盖默认值）。
